## P1 问题

1. **generic 机型把 relay 自建的虚拟平板开关当作硬件开关。**
   会让未知机型出现硬件 ON 反馈环，物理开关存在时还可能无法启动 relay。
2. **主循环缺少顶层异常隔离。**
   单次未捕获异常可能停掉 100 ms 状态机。
3. **硬件平板状态下策略历史可能无界增长。**
   长期运行时存在内存风险。
4. **手动测试的 root 助手存在 `/tmp` 符号链接竞态。**
   测试脚本可能被本地竞态利用。
5. **发布就绪度不足。**
   当时缺少许可证、真实源码地址、有效校验和、完整安装元数据和 clean-chroot 验收。

- 显示恢复日志的原子性、损坏处理与跨后端兼容。
- 平板模式下的方向锁、旋转顺序和 X11 触摸坐标。
- 休眠/唤醒后的策略锚点与硬件状态恢复。
- relay 热插拔、设备重发现和 TOCTOU 边界。
- UI 代理重连、同步状态、重复点击和无障碍。
- AUR 依赖、安装脚本、卸载残留和可复现构建。
